# Layrcake TypeScript SDK

Go-to-market infrastructure for AI agents: find leads, enrich and verify emails, read buying signals, research companies, and run email campaigns that a person approves before anything sends.

This is the official TypeScript client for the [Layrcake API](https://docs.layrcake.dev). It has no runtime dependencies. It works in Node 18 or later, Bun, Deno, Cloudflare Workers, Vercel Edge and other runtimes with `fetch`.

## Install

```sh
npm install layrcake
```

## Quickstart

Get an API key at [layrcake.dev](https://layrcake.dev) and set `LAYRCAKE_API_KEY`.

```ts
import { Layrcake, getApproval } from "layrcake";

const layrcake = new Layrcake(); // reads LAYRCAKE_API_KEY

const { result: found } = await layrcake.findLeads({ audience: "Heads of Sales at US software companies with 50 to 500 staff", limit: 5 });
const lead = found.leads[0]!;
const { result: enriched } = await layrcake.enrich({ person: { full_name: lead.full_name!, company_domain: lead.company_domain! }, want: ["work_email"] });
const email = enriched.contact?.work_email ?? lead.work_email!;
const { result: check } = await layrcake.verifyEmail({ email });
if (check.status !== "valid") throw new Error(`${email} is ${check.status}`);
const { result: draft } = await layrcake.createCampaign({ name: "Q4 sales leaders", leads: [{ email }], steps: [{ subject: "Quick question", body: "Hi {{first_name}}, ..." }] });
const preview = await layrcake.launchCampaign({ campaign_id: draft.campaign_id });
console.log("Ask a person to approve:", getApproval(preview)?.approvalUrl);
```

The last call sends nothing. It returns a preview and an approval link. Emails go out only after a signed-in person approves in the Layrcake console.

## Configuration

```ts
const layrcake = new Layrcake({
  apiKey: "lc_...", // default: the LAYRCAKE_API_KEY environment variable
  baseUrl: "https://api.layrcake.dev", // default
  maxRetries: 2, // default
  timeoutMs: 60_000, // per attempt, default
  fetch: customFetch, // default: the global fetch
});
```

The constructor throws if it finds no key. Keep the key on a server. Do not ship it to a browser.

Every method also takes per-call options as its last argument:

```ts
await layrcake.getMe({ timeoutMs: 5_000, maxRetries: 0, signal: controller.signal });
```

## Methods

Every method returns `{ result, layrcake, requestId }`.

- `result` is the outcome, typed from the OpenAPI spec.
- `layrcake` holds billing facts on metered calls: `request_id`, `credits_charged` and `credits_available`. It is `null` on endpoints that return none.
- `requestId` is the request id. Quote it to support.

Credit amounts are decimal strings, exactly as the API sends them, such as `"1.250000"`. The SDK never turns them into floating point numbers. Use a decimal library if you need to do arithmetic.

## Dry runs

Most paid verbs accept `dry_run: true`. The call returns a plan instead: the most it can cost, how many sources could answer, and any limit it would trip. Nothing is looked up, reserved or charged. The return type follows the flag.

```ts
const { result } = await layrcake.findLeads({ audience: "CFOs at UK fintechs", dry_run: true });
console.log(result.plan.would.maximum_credits);
```

`budget_credits` sets a spend ceiling for one call. A call that could cost more is refused before anything is charged.

## Idempotency

Paid and external calls take an `Idempotency-Key`. If you do not pass one, the SDK generates a UUID for each call and reuses it across its automatic retries. The API then returns the first outcome instead of running or charging twice.

Pass your own key when you may retry later, for example after a crash or a timeout:

```ts
await layrcake.createCampaign(params, { idempotencyKey: `campaign-${jobId}` });
```

When a call fails, `error.idempotencyKey` holds the key that was sent. Retry with it to get the original outcome. Endpoints without an idempotency key, such as `getMe`, never get one.

## Retries

The SDK retries `429`, `502`, `503` and `504` responses and network errors, up to `maxRetries` times (default 2). It waits with exponential backoff and jitter. It honours `Retry-After` and the API's `details.retry_after_seconds`. If the server asks for a wait longer than 60 seconds, the SDK throws instead so you can decide.

It never retries any other `4xx`. A `POST` is retried only when it carries an idempotency key, so a retry cannot act twice. Every write endpoint in the API takes one, and the SDK always sends one.

## Errors

Every error is a `LayrcakeError` with `status`, `code`, `message`, `details`, `requestId` and `idempotencyKey`. Subclasses let you catch by kind:

| Class | When |
| --- | --- |
| `AuthenticationError` | 401. The key is missing, wrong, revoked or expired. |
| `PermissionDeniedError` | 403. A missing scope, a paused agent, or a disabled feature. |
| `ApprovalError` | `confirmation_required`, or an approval that was declined, expired, superseded, cancelled or changed. |
| `InsufficientCreditsError` | 402, or a run budget reached. Top up or raise the budget. |
| `ValidationError` | 400 or 422. `details` usually names the field. |
| `NotFoundError` | 404. |
| `ConflictError` | 409, such as an idempotency key reused with different parameters. |
| `RateLimitError` | 429. `retryAfterSeconds` says when to try again. |
| `ServerError` | 5xx, such as `provider_unavailable`. |
| `APIConnectionError` | No response arrived. |
| `APITimeoutError` | The request passed `timeoutMs`. |
| `OperationTimeoutError` | `waitForOperation` ran out of time. |

```ts
import { InsufficientCreditsError, LayrcakeError } from "layrcake";

try {
  await layrcake.findLeads({ audience: "CTOs at Series A startups" });
} catch (error) {
  if (error instanceof InsufficientCreditsError) console.log("Top up at https://layrcake.dev");
  else if (error instanceof LayrcakeError) console.log(error.code, error.message, error.requestId);
  else throw error;
}
```

`code` is typed with every code in the spec, such as `insufficient_credits` or `provider_unavailable`. Branch on `code` for detail. `API_ERROR_CODES` lists them all.

## Background operations

Some calls start work that finishes later and return an `operation_id`. Examples are `researchCompany`, `prospectPicture` and a confirmed `setupSending`. Wait for it with `waitForOperation`:

```ts
const { result } = await layrcake.researchCompany({ company_domain: "acme.com" });
const operation = await layrcake.waitForOperation(result.operation_id, { intervalMs: 2_000, timeoutMs: 600_000 });
if (operation.state === "succeeded") console.log(operation.result);
```

It polls `GET /v1/operations/{id}` until the state is `succeeded`, `partially_succeeded`, `failed`, `cancelled` or `unknown`, then returns the operation. It does not throw on `failed`, so check `state`. `unknown` means a provider's outcome could not be confirmed and Layrcake is reconciling it. Do not repeat the action while it is `unknown`. Pass `signal` to stop waiting.

## Approvals

Nothing reaches a real person until a person on your side says yes. `launchCampaign`, `setupSending`, `replyToThread`, and `addLeads` on an active campaign first return a preview with a `confirmation_token` and an `approval_url`. A signed-in person approves in the Layrcake console. Then you repeat the call with the token, or the server runs it.

```ts
import { getApproval } from "layrcake";

const preview = await layrcake.launchCampaign({ campaign_id });
const approval = getApproval(preview);
if (approval) {
  console.log("Approve here:", approval.approvalUrl);
  // Later, after the person approves:
  await layrcake.launchCampaign(
    { campaign_id, confirmation_token: approval.confirmationToken },
    { idempotencyKey: `launch-${campaign_id}` },
  );
}
```

`isApprovalRequired(response)` is the same check as a type guard. The SDK never approves anything and has no way to.
